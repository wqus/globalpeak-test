# Использование ИИ и проверка

Инструмент: OpenAI Codex в этой сессии. Точная версия модели отдельно не фиксировалась. ИИ использован во всех трёх заданиях. Код, текст и макет создавались с его помощью; это раскрывается явно.

| Задание | Задачи ИИ | Как проверялось |
|---|---|---|
| 01 Мониторинг | Разбор бизнес-цели, схема данных, правила неоднозначности, код истории/дублей, тестовые ситуации, ограничения охвата, оценки | Исполняемые сценарии на 3 снимках, тест повторного импорта и отката, проверки цен/статусов и сбоя источника; условия Циан сверены с официальным источником |
| 02 Материал | Выбор акцента, редактура утверждений, композиция, SVG/HTML | Каждое утверждение сопоставлено с переданным исходником; финансовые обещания исключены; оригинал в SVG проверяется побайтно; макет просмотрен в браузере |
| 03 Публикация | Проект контракта, состояния, Id и хеш, код очереди, ошибки/повторы, тесты | Запуск 7 сценариев, проверки конкуренции, перезапуска, 409 и HTTP; реальные GP OS/Авито не тестировались |

Рабочие формулировки задач (смысл, не выданный за полный машинный лог):

1. «Спроектировать ежедневный мониторинг с разрешёнными входами, отдельно хранить объявление и объект; не считать исчезновение продажей и не объединять по одному адресу».
2. «Подготовить макет на реальном фото; не менять здание; не использовать цену, аренду и доходность без подтверждения; выделить источник каждого утверждения».
3. «Показать идемпотентный сценарий UUID/версия → валидация → очередь → fake-адаптер → возврат в advertising, включая 409 и таймаут после принятия».

Что пришлось ограничить в результате работы ИИ:

- Общедоступный API публикации не считать источником рыночного мониторинга.
- Локальную транзакцию fake-адаптера не выдавать за гарантию атомарности реального сетевого вызова.
- Написание адреса и условие 5% от РТО не превращать в подтверждённые факты.
- При статическом размещении показывать сохранённый прогон с подписью; не выдавать его за новое выполнение backend.
- Служебную версию карточки не использовать как внешний Id объявления.

Сначала 16 доменных проверок прошли, а 2 HTTP-проверки не выполнились из-за запрета локальных сокетов в sandbox (WinError 10013). После разрешённого запуска локальных тестов вне этого ограничения все 18 прошли. Это ограничение среды, не подтверждение внешних интеграций. Последующий расширенный итог тестов — в verification.json.

Тесты тоже подготовлены с помощью ИИ и не являются независимым аудитом. Бизнес-правила должны пройти приёмку брокером, совместимость API — проверку в согласованном тестовом контуре. Платные генераторы, внешние LLM-вызовы в приложении и скрытые подписки не запускались. Существующая сессия Codex может иметь свою стоимость, она не объявляется бесплатной.
