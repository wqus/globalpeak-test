# Тестовое задание GlobalPeak

**Абрамян Бен · тестовое задание GlobalPeak · 03.11.2026**

[Страница отчёта](https://wqus.github.io/globalpeak-test/) · [Репозиторий](https://github.com/wqus/globalpeak-test) · [Сборка и проверки](https://github.com/wqus/globalpeak-test/actions)

Три задачи в одном воспроизводимом пакете: история мониторинга, рекламный макет реального портфельного объекта и модуль обработки публикации через тестовый адаптер. Без платных зависимостей и реальных отправок.

## Запуск за минуту

Нужны Python **3.11+** и современный браузер. Сторонние Python-пакеты и Node.js не требуются. Проверено на Python 3.14 / Windows и в GitHub Actions / Ubuntu: 18 тестов проходят.

```sh
python -m tools.build
python -m unittest discover -v
python -m src.server
```

Открыть **http://127.0.0.1:8765**. Для другого порта: `python -m src.server --port 8766`.

В PowerShell при отсутствии `python` можно использовать `py -3`. Запускать команды из корня репозитория. Локальный сервер работает в foreground; Ctrl+C завершает его. Не открывать index.html как file://: загрузке JSON нужен HTTP.

## Что смотреть

1. **Мониторинг:** выбрать 02 ноября — видна цена 22 → 21 млн ₽; 03 ноября — сбой partner-b и сохранённые прежние наблюдения. Открыть карточку, увидеть основания и отдельные источники. Сравнить «не наблюдается» и «продано» — второе система не утверждает.
2. **Материал:** открыть макет 1080×1350, затем оригинальное фото. Фасад и окружение не изменены. Цена, аренда и доходность отсутствуют. Разные варианты адреса записаны как вопрос.
3. **Публикация:** выполнить «таймаут после принятия» — одна отправка, сверка и один объект в fake-приёмнике. Затем «неподтверждённые поля» — 422 и ноль внешних объектов. В сценарии 409 результат публикации не теряется.

При открытии на статическом хостинге работают навигация, фильтры, галерея и **сохранённые результаты настоящего запуска Python**. Кнопка нового выполнения отключена с объяснением. Никаких сетевых публикаций в браузере не имитируется. Для нового запуска кода нужен локальный сервер.

## Что работает и что спроектировано

**Работает:** транзакционное хранение снимков, идемпотентный импорт, простая классификация, точные связи по идентификатору помещения, кандидаты дублей по адресу/площади, история цены/статуса, диагностика сбоя/частичного обхода/объёма, CSV; макет на исходной фотографии; локальные GET/PATCH, 409, очередь, защита от повторной постановки, ограничение повторов, сверка неизвестного исхода, возврат статуса и ошибок.

**Не подключено:** сбор реальных объявлений, договоры с источниками, ежедневный планировщик и доставка уведомлений, production GP OS, загрузка реальных медиа, официальный коннектор Авито и модерация. Публикации в тестовом адаптере не доказывают совместимость с production API.

В production публикация через официальную автозагрузку/разрешённые отчёты требует актуальной схемы категории и доступа аккаунта. Страницы документации Авито не открылись в среде проверки. Схема XML и тарифы не считаются проверенными. Файл stage-2-types.ts не предоставлялся.

## Данные и права

`fixtures/property.json` и мониторинг содержат вымышленные адреса, цены, UUID/ID и адреса example.invalid. Переменная цена 24 → 23,5 млн ₽ относится только к учебному объекту. Единственный реальный объект — рекламный материал на основе переданных фото и текста объявления №8145299815; факты из объявления не приравнены к документам. Кадастровые сведения и финансовые документы не предоставлены.

Фото включены для выполнения тестового; права не переоформляются и открытая лицензия на них не заявляется. Перед публичным коммерческим использованием нужны разрешение правообладателя и проверка фактов. Исходные водяные знаки сохранены. Секретов, клиентской базы и production-ключей нет. Cookie/CSRF генерируются в памяти и не сохраняются в Git.

## Проверка

```sh
python -m tools.verify
```

Команда выполняет тесты и сохраняет `dist/data/verification.json`: количество/результат тестов, проверка внутренних ресурсов, контроль оригиналов и метка времени. В ограниченной среде могут потребоваться права на локальные сокеты для HTTP-тестов; сетевого обращения к Авито/GP OS нет. Локальная проверка одного окружения не заменяет CI или тестирование боевой интеграции.

## Публикация на GitHub Pages

Ручной workflow `.github/workflows/pages.yml` собирает отчёт, выполняет тесты, проверяет ресурсы и публикует только каталог dist. Результаты запусков: https://github.com/wqus/globalpeak-test/actions. Инструкция подготовлена по официальной документации https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages.

1. Создать GitHub-репозиторий и отправить текущий Git-коммит, без runtime и секретов.
2. В Settings → Pages выбрать Source: GitHub Actions. В Actions открыть Verify and publish report → Run workflow. Публикация произойдёт только после успешных проверок. Не выбирать просто корень main: там нет index.html.
3. На публичном хостинге будет доступен статический отчёт и сохранённые прогоны; локальный Python backend туда не разворачивается.
4. Проверить страницу и репозиторий без авторизации, картинки, загрузку SVG/CSV/JSON и работу относительных ссылок из подпути репозитория.
5. Две публичные ссылки для передачи результата расположены в начале README. В отчёте приведены график доступности и ориентировочная дата начала работы.

В GitHub Actions адреса страницы и репозитория подставляются в опубликованный отчёт автоматически из контекста репозитория. Локальная команда без параметров сохраняет подпись локальной версии. Параметры --public-url и --repo-url готовят артефакт публикации, но сами его не размещают.
